# TradeLift — Default Design System (Jarvis, permanent baseline)

**Owner:** Jarvis (PM/AI) · **Effective:** 2026-09-15 · **Scope:** Every NEW website or web app built for Pablo, unless Pablo explicitly gives different design instructions.

> **IMPORTANT:** Do NOT redesign, modify, or imitate any existing website (incl. the live TradeLift site) unless specifically asked. This file defines the DEFAULT design system for every NEW website only.

The goal: feel like a strong professional product designer built it — NOT a generic AI/vibecoded website.

---

## 1. AVOID THE "AI/VIBECODED" LOOK

Do not automatically use trendy AI-generated SaaS patterns just because they are common:

- excessive purple/black combinations
- harsh gradients
- neon colors
- excessive glassmorphism
- excessive rounded cards
- generic Bento grids
- random glowing blobs
- radial gradient backgrounds
- dotted grids
- sparkle icons
- Lucide icons everywhere
- animated arrows
- fake terminal windows
- excessive hover animations
- giant gradient text
- generic AI illustrations
- unnecessary decorative elements
- checkmark bullet lists everywhere
- "It's not X, it's Y" marketing copy
- three generic pricing tiers when they aren't actually necessary
- fake testimonials
- fake logos
- fake statistics
- generic pastel SaaS colors
- excessive soft shadows
- excessive pill-shaped UI
- excessive corner rounding

Use these elements ONLY when they genuinely improve the specific product.

## 2. DESIGN COMES FROM THE PRODUCT

Before writing UI, understand: what the product does, who uses it, what action matters most, what information users need, what visually communicates trust, what should receive the most attention. Then build the interface around those requirements. Do NOT start from a generic SaaS template and fill it with different text.

## 3. VISUAL HIERARCHY

Every page has an obvious hierarchy. User immediately understands: what this is, why it matters, what to do next. Use typography, spacing, size, positioning, contrast, and layout — not gradients and decoration.

## 4. TYPOGRAPHY

Intentional typography: strong readable headlines, restrained font weights, comfortable body text, clear hierarchy, consistent line heights, appropriate letter spacing. Not every heading enormous. Avoid excessive all-caps.

## 5. COLOR

Restrained palette: strong neutral foundation + one primary brand color + one or two supporting colors when necessary. Colors communicate hierarchy and meaning. No automatic purple/neon/gradients. If gradients: real purpose, subtle.

## 6. SPACING

Generous, consistent spacing. Visual rhythm via section spacing, content width, padding, alignment, whitespace. Whitespace is a design element. Don't fill every empty area with cards/illustrations/gradients/decoration.

## 7. LAYOUT

Layout appropriate to content: editorial, asymmetric, single-column, split-screen, dashboard, tables, timelines, comparison, product-focused, image-led, traditional grids. No default Bento grids. Don't force everything into cards.

## 8. COMPONENTS

Components must have a reason to exist. Cards = genuinely grouped information. Not every content piece inside a rounded rectangle. Clear purposeful buttons, simple forms, obvious navigation.

## 9. ICONS

Use sparingly. An icon must communicate something meaningful. No icon-per-bullet. No Lucide just because it's available. Prefer text, spacing, typography, or simple visual elements.

## 10. IMAGES

Strong real or relevant imagery when it improves the product. No automatic generic AI illustrations. Images support purpose, not fill space.

## 11. ANIMATIONS

Communicate state changes, transitions, hierarchy, interaction feedback. No decoration-only motion. Prefer subtle, fast, purposeful transitions.

## 12. RESPONSIVE DESIGN

Mobile-first, works on mobile / tablet / desktop / large desktop. Reconsider hierarchy and layout at breakpoints — don't just shrink the desktop layout.

## 13. ACCESSIBILITY

Semantic HTML, proper heading hierarchy, meaningful alt text, keyboard navigation, visible focus states, sufficient contrast, accessible form labels, ARIA only when necessary, reduced-motion consideration. Never an afterthought.

## 14. SEO + TECHNICAL QUALITY

Unique titles, meaningful meta descriptions, canonicals where appropriate, correct heading hierarchy, descriptive alt text, semantic HTML, sitemap when appropriate, robots.txt when appropriate, favicon, correct lang attribute, Open Graph metadata, structured data when relevant. Don't blindly add SEO that doesn't make sense.

## 15. PERFORMANCE

Lightweight. Avoid: massive JS bundles, unnecessary dependencies, huge images, duplicate libraries, excessive client-side JS, performance-hurting animation. Prefer optimized assets, lazy loading, code splitting, SSR/static generation, minimal dependencies.

## 16. SECURITY + PRIVACY

Auth security, authorization, input validation, safe uploads, secure API usage, secret protection, privacy policy when collecting data, terms when appropriate, data retention/deletion behavior. Never expose secrets/credentials in frontend code.

## 17. CONTENT

NO fake testimonials, logos, reviews, statistics, or fabricated claims. If real info isn't available, use neutral placeholders or structure for later insertion. Copy sounds like a real company, not AI filler. Avoid: "Unlock…", "Supercharge…", "Revolutionize…", "Next-generation…", "Powered by AI…" unless genuinely descriptive.

## 18. ERROR + EMPTY STATES

Design real states: loading, empty, error, success, disabled, validation. Don't rely entirely on browser defaults.

## 19. FORMS AND INTERACTIONS

Clear labels, sensible defaults, inline validation, useful error messages, confirmation for destructive actions, loading feedback. Never make the user guess what happened after clicking.

## 20. OVERALL AESTHETIC

The final result feels: intentional, premium, modern, clean, human-designed, product-specific, credible, fast, usable. NOT: AI-generated, template-generated, overdesigned, gimmicky, generic SaaS, "vibecoded".

---

## FINAL SELF-CHECK (before a NEW site is complete)

Ask: "Could someone immediately recognize this as a generic AI-generated website?"

If YES — remove unnecessary decoration, reduce gradients, reduce rounded cards, reduce icons, remove fake social proof, remove unnecessary animations, simplify the color palette, improve typography, improve spacing, make the layout more product-specific.

Also ask: "Does every major design decision have a reason?" If not, simplify it.

**Priority order:** 1. Functionality · 2. Usability · 3. Clarity · 4. Visual hierarchy · 5. Brand identity · 6. Performance · 7. Accessibility · 8. Decorative effects.

Build the website around the product — not around a trendy AI website aesthetic.
